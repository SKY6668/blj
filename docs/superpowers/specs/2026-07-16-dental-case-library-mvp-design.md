# 牙科病例库 MVP 设计

## 目标

交付一个可在手机和 PC 浏览器中演示的病例整理原型。医生可以使用演示账户登录，浏览、搜索、筛选、新建、编辑和展示匿名示例病例；可预览分享设置。原型不接收真实患者资料，不提供公网分享链接，也不调用云端服务。

## 范围

MVP 包含：

- 病例列表、关键词搜索、治疗类型/牙位/标签筛选。
- 病例新建和编辑：匿名病例编号、治疗类型、牙位、日期、标签、说明、术前/术后图片。
- 病例详情、术前术后对比、全屏展示册模式。
- 分享设置预览：有效期、允许访问次数和撤销状态的界面与本地状态。
- 账号密码登录界面、演示账户校验和本地会话状态。
- 本地演示数据，以及可替换的数据访问接口。

MVP 不包含：真实账户注册、真实密码存储或传输、找回密码、跨设备同步、真实患者姓名或联系方式、真实图片上传、二维码、真实分享链接、审计日志、服务器、数据库或云存储。

## 技术与结构

前端采用 uni-app X、Vue 3 和 TypeScript。首期只构建 H5 预览；页面结构和组件保持跨端兼容，后续在 HBuilderX 中构建 Android 与 iOS。

数据层定义 `CaseRepository` 接口，页面和组件只能通过该接口读取和修改病例。第一版使用 `LocalCaseRepository`：首次启动时载入匿名演示病例，后续修改写入本地存储。未来服务器阶段新增 `ApiCaseRepository`，不改变页面的业务调用方式。

## 数据模型

`CaseRecord` 包含：`id`、`caseCode`、`treatmentType`、`toothPositions`、`treatmentDate`、`tags`、`summary`、`images`、`createdAt`、`updatedAt`。

`CaseImage` 包含：`id`、`label`（术前/术后/过程）、`previewUrl`、`isDeidentified`。演示图片使用应用内占位图；新增病例仅保存用户选择图片的本地预览，不上传任何文件。

`ShareSettings` 包含：`caseId`、`expiresAt`、`maxViews`、`revoked`。它只驱动 UI 状态，不生成可访问的地址。

`DemoAccount` 包含：`id`、`displayName`、`email`、`password`。演示账户仅存放在前端源代码的演示数据中；登录成功后仅在本地存储账户 ID，不保存密码。演示账户用于验证页面流程，不能视为安全认证。

## 页面与流程

1. 启动页显示账号密码登录；仅通过演示账户校验后进入病例列表。
2. 首页显示病例列表、筛选项和“新建病例”入口。
3. 用户筛选或搜索后，列表即时更新；点击病例进入详情。
4. 新建/编辑页要求填写匿名病例编号、治疗类型和至少一个牙位；保存前须勾选“已脱敏”。
5. 详情页按照术前、过程、术后分组展示图片，可进入展示册模式。
6. 分享设置页允许设置有效期和访问次数、标记撤销，并明确提示“原型不会生成真实链接”。

## 错误处理与隐私边界

- 表单缺少必填项、未确认脱敏或图片类型不支持时，不允许保存并显示字段级提示。
- 演示账户不存在或密码不匹配时，不创建会话并显示登录失败提示；页面明确标注“演示登录，不可用于真实账户”。
- 本地存储读取失败时，恢复匿名演示数据并提示用户；不尝试读取或上传任何外部病例文件。
- 所有示例文本和图片均为虚构占位内容，不出现真实姓名、联系方式、病历号或人脸照片。

## 验收标准

- 在桌面浏览器和移动浏览器中可完成新建、编辑、搜索、筛选、查看详情和展示册流程。
- 使用指定演示账户可以登录、刷新后保持会话，并可主动退出登录。
- 刷新页面后，已保存的病例元数据、筛选状态和分享设置仍可恢复。
- 分享页没有真实 URL、二维码或外网请求。
- 单元测试覆盖数据仓库、筛选逻辑和表单验证；H5 构建命令成功完成。

## 后续衔接

Docker 与服务器环境就绪后，按相同接口接入 NestJS API、PostgreSQL、MinIO/COS、真实账户注册与登录、密码哈希、密码重置、登录会话、短时文件签名、审计日志和真实受控分享。届时必须重新审查隐私、患者授权和数据删除流程。
