# 牙科病例库：首版设计

## 目标与范围

面向中国大陆市场，先由单个牙科医生使用，用于收集、检索、展示和受控分享病例。系统覆盖 Android、iOS 与 PC 浏览器；首版不包含诊所多人协作、患者在线问诊、诊断建议或治疗决策。

首版包含：

- 手机拍摄或选择图片并上传。
- 按病例、牙位、治疗类型、日期和标签整理资料。
- 生成适合 PC 和手机阅读的病例展示册。
- 生成可设置有效期、可撤销的分享链接或二维码，供同行交流。

## 技术架构

前端使用 uni-app X、Vue 3 与 TypeScript，一套代码构建 Android、iOS 和响应式 Web。PC 端首期以网页形式提供，不开发 Windows 或 macOS 原生客户端。

本地开发环境使用 Docker Desktop 编排以下服务：

- NestJS API：身份认证、病例管理、分享链接、审计记录和权限校验。
- PostgreSQL：用户、病例元数据、标签、分享记录与审计日志。
- MinIO：原始图片、脱敏图片及附件；通过 S3 兼容接口访问。

后期将相同容器部署到腾讯云服务器，图片服务迁至腾讯云 COS；后端统一使用 S3 兼容存储接口，避免业务代码重写。正式公网服务前配置域名、HTTPS、备案、备份和监控。

## 数据与权限

病例使用随机 ID，不以患者姓名作为主标识。病例记录至少包含：匿名病例编号、治疗类型、牙位、日期、标签、说明、图片组和脱敏状态。

原始图片仅本人账户可访问；展示或分享时仅允许选定的、确认脱敏后的图片。分享链接必须设置有效期、支持手动撤销，并记录创建、访问和撤销事件。首版默认不开放公开搜索、下载原图或评论区。

## 安全与合规边界

上传前提示用户确认患者授权和资料脱敏；系统不存储不必要的身份信息。接口需要登录令牌验证，文件通过短时签名 URL 访问；数据库与文件存储只在 Docker 内网暴露。生产环境启用 HTTPS、备份、最小权限、访问审计和密钥管理。

应用定位为病例资料管理与展示工具，不提供自动诊断、治疗建议或医疗决策。上架前准备隐私政策、用户协议、账号注销与数据删除机制，并根据实际数据处理方式完成应用商店隐私申报。

## 开发环境

开发电脑建议 Windows 11、16GB 及以上内存、512GB 及以上 SSD。需要安装 Node.js LTS、HBuilderX、Docker Desktop、Git、Visual Studio Code、PostgreSQL 客户端和 API 调试工具。Android 使用真机调试；iOS 的真机调试、打包和 App Store 提交需要 macOS 与 Xcode，可在上架准备阶段使用 Mac mini 或云端 Mac。

## 实施顺序

1. 安装并验证本地开发环境。
2. 创建跨端前端和 Docker 本地后端骨架。
3. 实现登录、病例、图片上传和检索。
4. 实现病例册、受控分享与审计。
5. 使用真机验证、准备隐私材料，再部署腾讯云并提交应用商店。
